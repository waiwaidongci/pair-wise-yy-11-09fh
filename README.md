# 种质库跨库调拨复核台 · GRB-62010

种质库跨库调拨业务的复核工作台（前端单页应用，数据保存在浏览器 localStorage）。

## 业务规则

1. **登记**：批次号、作物、来源库、封条编号、发芽率、含水率、活力检测日期、目标库位。
2. **强制复检红线**（命中任一即只能转入复检，不能直接批准）：
   - 含水率高于 13%；
   - 活力检测日期距今超过 90 天；
   - 目标库位已被在储批次或其他有效调拨单占用。
3. **同一封条重复申请**：检测结果（发芽率/含水率/活力日期）与首次完全一致时，沿用首次结果，不生成新单、不重复占用资源，仅在原单累计重复次数并写入历史。
4. **新检测即失效**：同一封条提交与首次不同的检测结果时，旧的在途申请/已批准调拨单立即失效，封条与库位占用同步释放，原调拨单标记作废。
5. **复检记录**：检测人、复测含水率、复测发芽率、处置结论（合格通过 / 干燥后重检 / 降级使用 / 报废销毁）及确认库位。
   - 合格通过：同时占用封条与目标库位，生成调拨单号（DB-日期-序号）；
   - 其他结论：不占用封条与库位，工单按处置结论退回。
6. **一致性**：复核队列、库位状态图、封条占用清单、调拨台账与每单历史均由同一份状态派生，任何变更后批次、库位与历史保持一致；刷新页面后数据通过 localStorage 保持。

## 技术栈

React 19 + Vite + TypeScript（无后端，localStorage 持久化）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62010；页面内「恢复演示数据」可随时重置为内置种子数据。
